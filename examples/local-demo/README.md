# 可直接操作的本地验收 Example

这是一个连接真实 Keycloak、oCIS、PostgreSQL、NATS、Meilisearch、转换服务及 React 网页的本地示例，不是静态界面，也没有假登录、假上传或预制搜索结果。

首次启动会创建两个随机密码的合成账号，实际完成 PKCE 登录、原生存储预检、后台授权、tus 上传、两个不可变历史版本、正文转换、索引查询及 PDF 光栅预览。只有这些检查全部通过才报告启动完成。**真实浏览器操作、完整 Docker Compose 启动结果，以及全规格验收结果是不同证据，不因脚本存在而自动通过。** 当前交付的准确运行记录见仓库的验收报告。

## 1. 准备环境

- Linux 的本地 Docker Engine，或 macOS Docker Desktop 的本地 Linux 容器引擎；必须已启动，不只是安装 CLI。Windows 请在 WSL2 内使用 Linux 工具及本地 Docker 集成。
- Docker Compose v2.39.4 或更新版本、Python 3.10 或更新版本。
- 可以拉取仓库锁定的镜像、下载 npm/pip/Go 构建依赖；首次构建可能需要数分钟或更久。
- 主机的 `127.0.0.1:8080` 端口空闲。示例固定使用 `http://drive.localhost:8080`，不自动切换端口，避免 OIDC issuer、cookie 与回调地址错配。

此示例只在本机 loopback 上开放网关，所有依赖留在 Docker 私有网络。不要映射到公网，不要使用真实身份账号、生产密码或敏感文件。HTTP 只用于本机演示，不适合作为生产部署模板。

## 2. 一条命令启动

在解压后的仓库根目录执行：

```sh
export DEMO_RUNTIME="$HOME/.local/share/agent-clouddrive-example"
python3 examples/local-demo/demo.py start --runtime "$DEMO_RUNTIME"
```

不传 `--runtime` 时，默认目录是 `~/.local/share/agent-clouddrive-demo/<源码路径的短哈希>`；启动和状态输出会显示实际路径。以下步骤统一使用显式的 `DEMO_RUNTIME`。

`DEMO_RUNTIME` 必须在源码目录之外，且不能是已有外部应用的数据目录。启动器生成独立的随机 Docker project 名称，运行数据目录权限为 `0700`，登录凭据文件为 `0600`。同一目录重复启动会保留同一批账号、文件和卷。

启动会按顺序执行：

1. 生成随机合成 owner/reader 账号与私有服务凭据。
2. 构建真实前端、API、worker、文本/PDF 转换器及预览器，执行数据库迁移。
3. 保持集成开关关闭，先验证真实 PKCE、标准 token exchange、oCIS 原件与条件写入、历史读取和移动后的历史保留。缺任何证明都不会自动放开开关。
4. 仅对本例新生成的 owner 账号，通过 Keycloak 的独立离线授权流程同意后台读取与转换；随后通过真实业务 API/tus 写入样例。
5. 等待当前源版本真正完成转换且可搜索，并实际读取受控 PDF PNG 页面。仅“上传已保存”不算样例验收完成。

运行 `start` 即选择为这些**新建的本地合成账号**完成上述演示授权。它不会使用你已有的真实账户，不会创建任何公开分享，也不会替你确认网页中的分享请求。

若中途失败，命令返回非零，不会把失败当成功，不会删除已保存数据。修复具体依赖或端口问题后，对同一目录重新运行。遇到结果不明的原生写入时，示例会停止并保留记录，不盲目重做。

## 3. 打开网页并登录

浏览器打开：`http://drive.localhost:8080`

不要换成 `http://localhost:8080` 或 `http://127.0.0.1:8080`。OIDC 配置绑定的是原始地址。如果浏览器不能解析 `drive.localhost`，先确认该域名在本机解析到 `127.0.0.1`，不要把凭据提交到其他域名。

在自己的终端查看本次随机账号：

```sh
cat "$DEMO_RUNTIME/credentials.json"
```

- `owner.username` / `owner.password`：拥有样例文件的用户。
- `reader.username` / `reader.password`：用于验证私有隔离和收到分享的另一用户。

请只在自己的终端查看，不要把该文件、截图、终端历史或整个 runtime 目录发给其他人。启动器不会在普通状态输出中打印密码。

在登录页保留验收需要的读取、上传、删除、恢复、转换及分享请求权限，点击登录，在 Keycloak 中使用 owner 账号并检查授权内容。登录成功后应进入“我的文件”。这些是实际账号及实际 OAuth 授权，不是演示用固定 bearer token。

## 4. 验证后台处理与初始样例

“我的文件”中应有 `验收样例-xxxxxxxx` 文件夹，内含：

- `验收说明.md`：同一个文件的两个真实源版本。
- `搜索样例.txt`：带本次唯一搜索词的中文纯文本。
- `受控预览.pdf`：运行时生成的标准一页文本 PDF，供真实 PDF 转换与预览。

文件来自运行时的 `samples/` 目录，源码包不夹带随机凭据、预生成索引或二进制构建产物。

初始 owner 的后台授权已在第 2 步独立完成，因此网页可能不再显示“启用离线后台转换”提示。若你在独立账号中看到该提示，点击“前往授权”，在身份服务中核对离线访问并同意，再回到网页。上传成功不等于后台处理成功；尚未授权、转换失败、部分完成应保持真实状态，不能当作“已就绪”。

## 5. 上传与搜索

1. 点击“上传文件”，选一个不含真实敏感内容的 `.txt`、`.md` 或文本型 `.pdf`。
2. 观察 Uppy 的真实传输进度，等待“原件已保存”。然后刷新文件列表，继续等转换状态完成。
3. 点击“搜索内容”，搜索文件正文中的一个独特词，不只搜文件名。
4. 打开搜索结果，核对返回源版本、当前源版本与完整性状态。

要找到三个初始样例，可在自己的终端读取本次唯一搜索词：

```sh
python3 - "$DEMO_RUNTIME/demo-result.json" <<'PY'
import json, sys
print(json.load(open(sys.argv[1], encoding="utf-8"))["search_marker"])
PY
```

该词以 `demo` 开头，每个运行目录不同。初始检查要求命中的三份文档都来自各自当前源版本，且状态是 `ready`；不会拿旧版本或部分转换结果冒充成功。

## 6. PDF 预览和历史版本

1. 打开 `受控预览.pdf`，查看“转换正文”，应出现该 PDF 的文字。
2. 切到“原件预览”。应显示实际生成的一页 PNG 光栅预览和匹配的源版本 ID。页面不加载公开 oCIS 链接，也不执行原文脚本或宏。
3. 打开 `验收说明.md`，切到“历史版本”，应看到 v1 和 v2。
4. 选择 v1，点击“下载原件”，可读到“第一版”；选择 v2 则是“第二版”。选择旧版本不会覆盖当前内容。
5. 如要尝试更新，使用文件操作菜单的“上传新版本”，而非假设同名新上传会静默覆盖。请先记录当前状态，因为严格基线检查会识别你改动后的样例。

预览页明确显示当前原件版本；选中历史版本时，历史原件通过下载读取，不能把当前预览误当作历史预览。

## 7. 分享必须由你人工确认

示例不会自动创建或批准任何分享。推荐先验证指定用户分享，不要直接建立公开链接。

先读取 reader 的**业务系统用户 ID**，不是 username、显示名或 Keycloak 的 subject：

```sh
python3 - "$DEMO_RUNTIME/demo-result.json" <<'PY'
import json, sys
print(json.load(open(sys.argv[1], encoding="utf-8"))["reader_id"])
PY
```

1. 以 owner 登录，打开一个测试文件，点击“请求分享”。
2. 选择“指定系统用户”，填写上面的精确 reader ID，核对只读/下载权限、版本策略标签与到期时间。默认分享最新版；如需固定历史版本，应先在详情的“历史版本”中选 v1，再点击“请求分享此历史版本”。分享弹窗没有切换版本的下拉框。
3. 点击“创建待确认请求”。**这一步还没有开放访问。**
4. 在“确认开放文件访问”中再次核对对象、文件、版本、权限和有效期，勾选确认，再点击“确认并开放访问”。批准需要实际网页会话和 CSRF。
5. 如需测试撤销，在“分享管理”撤销该分享，再用 reader 刷新验证失效。

未登录链接访问者是另一种可选分享方式，只有你明确选择并再次确认才会创建；它只提供受控预览。不要把公开链接发到不应访问的人手中。

## 8. 退出并验证 reader 隔离

先在右上角点击“退出登录”，再以 reader 登录。也可以使用另一个隐私浏览器窗口，避免沿用 owner 的 Keycloak SSO 会话。

- 人工分享之前，reader 的“我的文件”没有 owner 样例，搜索初始唯一词也不应命中 owner 文件。
- owner 人工确认分享后，reader 在“分享给我”查看允许的内容；不能编辑，也不能把收到的分享当作自己的 Agent/MCP 搜索资料。
- 分享撤销、源文件删除后，reader 原有访问应失效。

## 9. 回收站与恢复

切回 owner：

1. 对测试文件执行“移入回收站”，核对确认内容。
2. 当前文件列表与当前搜索入口不应继续暴露该文件；reader 原分享访问也应失效。
3. 打开“回收站”，点击“恢复”，核对目标目录与文件名。同名冲突不会静默覆盖。
4. 恢复后查看历史版本，旧版本仍存在。原分享**不会**自动重新开放，需要新的人工确认。

删除是业务回收，不是物理清理。这个示例不提供清空历史、永久删除或自动删除卷的命令。

## 10. 状态、严格检查与停止

```sh
python3 examples/local-demo/demo.py status --runtime "$DEMO_RUNTIME"
python3 examples/local-demo/demo.py check --runtime "$DEMO_RUNTIME"
python3 examples/local-demo/demo.py stop --runtime "$DEMO_RUNTIME"
python3 examples/local-demo/demo.py start --runtime "$DEMO_RUNTIME"
```

- `status`：显示当前容器状态和上次完整样例检查时间，不把历史通过冒充本次检查。
- `check`：重新登录并严格检查初始样例的原件、历史、当前源转换、搜索、受控预览和 reader 隔离。你修改、移动或删除了样例，或者主动分享给 reader，检查可能不再通过，这是发现真实变化，不会自动覆盖你的操作。
- `stop`：只停止本项目容器，保留账号、Docker 卷及上传数据。
- 再次 `start`/`restart`：复用本次 runtime，保留用户改动；已验证的示例只做实时登录/API 就绪检查，不重置样例或新建一份同名数据。

运行日志和诊断可能含本地配置，请先检查脱敏后再分享。不要手动将集成开关改为 true；只有真实原生预检完成才允许启动器启用。

## 边界与证据

这是较轻的**本地 core workflow**：原件使用 oCIS 本地存储驱动，派生产物使用私有本地卷。所有上述业务仍走同一真实应用与授权边界，不用 mock 替换关键服务。

本例不启动 RustFS/S3、PaddleOCR 模型、kkFileView/LibreOffice Office 预览，也不配置外部视觉模型。文本型 PDF、文本/Markdown 转换和 PDF/图片的受控光栅预览属于本例范围；扫描件 OCR、图片描述、Office 预览等可能返回依赖不足或 `partial`，**不得把这些结果标成完整就绪**。Peri 实际客户端、10 GiB 中断续传和容量/故障验收仍以各自独立验收记录为准。

本目录 `test_*.py` 是离线决策、边界、幂等与安全契约测试，不是 Compose/native/browser 通过证据：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s examples/local-demo -p 'test_*.py' -v
```

私有 runtime 中的 `preflight-result.json` 和 `demo-result.json` 仅在对应真实操作通过后记录成功。`readiness-result.json` 则只证明本次登录/API 可用，不代表重新验证过用户已经改动的样例。源码发布包不应包含这些本机运行文件或凭据。
