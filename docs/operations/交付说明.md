# Agent CloudDrive v1 交付说明

## 结论

代码已实现，并通过本包记录的源码自测与多条真实依赖集成测试。**这不等于原规格全部验收通过，也不是生产上线批准。** 未完成项目明确列在 `acceptance.json` 和 `acceptance.md`，发布检查会保持非零退出码，不会把跳过测试算作通过。

## 已实际通过

- Go：75 个顶层测试，另含 34 个子测试；开启 race detector，真实 PostgreSQL/NATS/Meilisearch 参与对应集成测试。
- 前端：50 个测试、TypeScript 检查、生产构建，使用真实 Uppy tus 客户端。
- 转换与预览：35 个测试，含真实 AnyDoc、CPU PaddleOCR，以及 DOCX/XLSX/PPTX 经 kkFileView/LibreOffice 转 PDF 后输出 PNG。
- 部署配置：5 个测试，含真实 RustFS 桶初始化与重复执行。
- 发布门禁校验器：20 个测试，覆盖证据缺失、篡改、过期源码摘要、错误的“全部通过”等情况。
- 原生完整业务链：真实 Keycloak 登录/PKCE/离线授权、官方 oCIS 上传、下载校验、NATS 后台处理、Meilisearch 检索同一新文件；MCP 2026-07-28；双用户隔离、scope、覆盖冲突、幂等提交、历史读取、删除/恢复、交互确认分享及 Agent 禁止读取收到的分享。

单独的原生 oCIS/RustFS 测试与带替身的用例层测试有明确标注，不能混为一谈。失败后修复的安全回归证据也保留在包内，并由最终通过记录说明结果。

## 尚未满足的关键条件

- 当前环境没有可运行的 Docker/Compose 引擎，只完成配置校验和原生依赖运行，不能宣称容器部署验收通过。
- 当前环境不能启动真实 Chromium，因此没有执行规格要求的真实浏览器 10 GiB Uppy 中断续传专项。DOM/传输测试不是替代品。
- 没有真实 Peri 客户端联调记录，不能用官方 SDK 测试替代。
- 没有配置外部视觉描述模型；需要描述但无法完成的内容会明确返回 partial，不伪造描述成功。
- 其余部分验收项，包括完整部署链匿名日志验证、完整 S3 应用路径及特定故障/格式场景，以验收矩阵为准。

## 使用顺序

1. 阅读根目录 `README.md`、`docs/operations/deployment.md` 与 `docs/operations/known-limitations.md`。
2. 在具备 Docker Engine 的测试主机，按部署说明生成本地密钥与配置，再运行 Compose。压缩包不包含真实密钥、令牌、运行数据库或模型权重。
3. 运行 `scripts/selftest.sh`；需要真实集成测试时，按 `docs/operations/selftest.md` 提供独立测试环境。
4. 运行 `python3 scripts/release-readiness.py`。当前应输出 NOT RELEASE READY，退出码 1 表示证据有效但仍有未完成门禁；退出码 2 表示证据或源码摘要无效。
5. 在完成全部必需门禁并补齐真实证据前，不把系统当作已验收生产服务。

ZIP 内含源码、锁定依赖、Compose、迁移、OpenAPI/MCP 合约、测试、示例文件、操作说明和脱敏测试记录；`SHA256SUMS.json` 可校验每个交付文件。
